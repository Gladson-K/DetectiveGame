# MARKED - Implementation Notes (Version 2)

Technical map of the codebase and the decisions behind it. For *using* the game see
`README.md`; for *authoring content* (tales, characters, portraits) see `V2_AUTHORING_GUIDE.md`.

## Runtime flow
1. `ProjectSetup` (editor) creates `Assets/Scenes/Main.unity` with a single `GameController`.
2. `GameController.Awake` builds the UI root and shows the main menu.
3. Menu -> `ShowTale` -> `BuildArcSection` -> `StartCase`.
4. `StartCase` asks `CaseGenerator` for the next unsolved case, clears the old screen,
   builds the room (`CrimeSceneBuilder`), the HUD (`InGameUI`) and the clue systems.
5. Player collects clues (`CluePickup` -> `ClickDetector` -> `ClueManager`), reads the
   Journal / Persons panels, and accuses via `CharacterPanelUI`.
6. `ConfirmAccuse` -> `DoAccuse` -> correct: `OnCaseSolved`; wrong: +30s, tip after two misses.
7. Solving every case in an arc arrests the menace; `NextUnsolvedCase` continues the arc.

## Systems
- **SeedService** - the player's detective identity. `UserSeed` (PlayerPrefs) + `IdentityCode`.
  Deterministic `StableHash`; progress keys `solved_*`, `arrest_*`, `roll_*`; `ResetIdentity`
  deletes all of them. This is the single source of per-player randomness.
- **CaseGenerator** - pure generation, cached per `tale|arc|seed|roll`. Picks a victim (from the
  arc's cities), a culprit (`canBeCulprit`), 3-5 suspects, then 3-4 Guilty + 2 Herring + 1-2 Flavor
  clues, guaranteeing the killer is always nameable from the clues. Dedupes clue ids and resolves
  clue implication names. Victim/culprit are used up before reuse so an arc feels varied.
- **TaleLibrary / TaleModels** - loads `Resources/Tales/*.json` as `TextAsset`, parses into
  `TaleDef`/`ArcDef`/`CharacterDef`/`ClueSpec` and validates. `ClueSpec.InArc` scopes clues to arcs.
- **CrimeSceneBuilder** - three room layouts, arc-tinted theme, victim portrait frame + name,
  a 12-slot shuffled spawn grid, mark-shape builders (X, infinity, bolt, wave, claw, triangle, circle).
- **ClueManager / ClickDetector / CaseCompletionHandler** - collection counter, physics raycast
  (mouse + touch), "all clues found" toast. Kept close to V1.
- **InGameUI** - HUD (counter, timer, Journal/Persons/Accuse/Menu), briefing "CASE FILE" card,
  toast, solved overlay, plus `PlayScreenRefs` handed to `GameController`.
- **MainMenuUI** - identity bar, sound toggle, tale cards (portrait grid + progress + Open File +
  Reshuffle when untouched), case slots with codes/status.
- **CharacterPanelUI** - Persons of Interest: suspect cards with portrait, role, alibi, statements
  and Accuse buttons; reveal-culprit mode for the solved overlay; P to toggles.
- **PortraitLibrary** - loads `Resources/Portraits/{id}` sprite, else draws a deterministic
  coloured placeholder from the character id/colour.
- **SfxBank** - procedurally generated audio clips (click/open/found/wrong/solved/arrest/accuse),
  so no audio assets are required.
- **CaseTimer** - counts up; `AddSeconds` for penalties.
- **UIKit** - runtime UI helper (panels, text, buttons, `SmallButton`, `Img`, `Portrait`, `Scroll`).

## Editor tools
- **ProjectSetup** - creates/repairs the scene and build settings; sets product name.
- **ContentPostprocessors** - force-imports `Resources/Portraits/*` as Sprites (Single, no mipmaps).
- **ContentValidator** - `Detective Game > Validate Tale Content`: missing/duplicate ids, thin
  arc pools (victims/culprits/guilty/herring), unknown implications, and missing portraits.
- **BuildScript** - one-click Windows/macOS/Linux/Android/WebGL builds into `Builds/`.

## Deviations from the original spec (and why)
- Everything (scene, UI, props) is generated by code - no manual Inspector wiring.
- Content is JSON under `Resources` so it loads synchronously on every platform (incl. Android/WebGL,
  where StreamingAssets would need `UnityWebRequest`).
- Legacy `UnityEngine.UI.Text` instead of TextMeshPro (no import step).
- The Journal/Persons keys live on always-active HUD components, not the hidden panels, so toggles
  and subscriptions keep working when a panel is closed.
- `ClueDefinition` dropped as a ScriptableObject and became a plain runtime class, because cases are
  generated per player rather than authored as static assets. `CaseDatabase.cs` (V1) was removed.
- Intentional V2 scope: deduction, accusation, multiple tales, randomization, portraits, arrests.
  Deliberately still out of scope: voice/recorded audio, text-localisation, cloud saves, hint system.

## Verification performed
- All runtime + editor C# compile-checked against Unity API stubs (net8.0, `LangVersion 9`).
- A content validator + a generation simulator confirmed every arc produces solvable cases
  (culprit always among suspects, victim excluded from suspects, >=3 guilty clues implicating the
  culprit, >=2 herrings implicating innocents, unique clue ids) across 12,000 random rolls.
